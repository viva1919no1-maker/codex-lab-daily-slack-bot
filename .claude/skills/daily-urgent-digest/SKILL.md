# Daily Urgent Digest（毎朝の至急ダイジェスト）

出典: executive-syncの「連絡のトリアージ」を毎日自動で回すために切り出したスキル。`試して！`での実テストで「至急2件」が依頼してはじめて見つかった反省から作成（依頼なしでも毎朝検知される状態にする）。

## 目的
取締役・オーナーが明示的に依頼しなくても、毎朝1回「今日中に対応しないと詰む項目」だけを検知して知らせる。見落としリスクをゼロにすることが目的なので、対象は絞り、ノイズを増やさない。全件トリアージや週次レポートはexecutive-syncに任せる。

## スキャン対象チャンネル
- #board-room
- #vivaworks
- #ceo-office
- #all-vivainc

（チャンネルが増えたら追記する）

## 抽出基準（「今日中に対応必須」と判定する条件）
以下のいずれかに当たるものだけを拾う。
- 「至急」「本日中」「今日中」「期限」などのキーワードを含み、期限が今日または明日の営業開始前
- 日程・金額・契約など確定回答を待っている未読スレッドで、相手の返信期限が近い
- ツール・連携の障害報告（例: Chrome拡張切断）で、放置すると業務が止まるもの

上記以外（「いつかやる」系のタスクなど）は拾わない。

## 実行手順
1. 対象チャンネルを `slack_read_channel`（直近24〜48時間・目安20〜30件）で読む
2. 抽出基準に当たる項目だけを残す
3. 0件でも「本日は至急対応なし」と明記して送る（検知が動いている確認のため、無言にしない）
4. 出力は結論→根拠→次アクションの順でまとめる
5. オーナー宛のSlack DM（user_id: `U0B4P6192CD`）に `slack_send_message_draft` で下書きを作成する。**`slack_send_message`（即時送信）は使わない** — Slackコネクタ側の承認ゲートにより自動実行（Trigger経由）では失敗することを確認済み（2026-06-23テスト）。下書きならゲートを通過し、オーナーがSlackを開いて送信ボタンを押すだけの状態になる
6. 返信文案の作成・送信、金額提示、日程確定は行わない（検知と報告のみ。取締役会2026-06-20決定のL0〜L3区分に準拠し、L2/L3はオーナー・各取締役が実施）
7. 同一チャンネルに既存の下書きが残っていると `draft_already_exists` エラーになる。その場合は新規作成を諦めて「前回の下書きが未送信のまま残っています」と一言添えるだけにする（上書きはしない）

## 定時実行の設定（初回のみ・オーナー作業が必要）
このスキル単体では「毎日9時に自動実行」までは実現できない（Slackのスケジュール送信は1回分の固定文面の予約のみで、毎日新しいデータを読みに行く処理とは別物）。毎朝の自動実行には、claude.ai/code/routines の「Routines」機能（旧称・通称「Triggers」）でスケジュール実行を設定する。手元のツールからは作成できないため、オーナー自身がWeb UIで以下を行う。
1. https://claude.ai/code/routines を開き「New routine」をクリック
2. 名前を付け、プロンプトに「`codex-lab-daily-slack-bot` リポジトリの `daily-urgent-digest` スキルを実行して、本日中に対応必須な項目を抽出し、オーナー宛Slack DMに下書きを作成して」のように自己完結した指示を書く（Routineは無人実行のため文脈なしで動く前提で書く）
3. リポジトリに `codex-lab-daily-slack-bot` を追加、環境は Default で可（SlackはMCPコネクタ経由でAnthropic側を通るため追加のネットワーク許可は不要）
4. トリガーで「Schedule」→「Daily」を選び時刻を設定。**時刻はアカウント/ブラウザのローカルタイムゾーンで解釈される**ため、JST 9:00に相当するローカル時刻に変換して入力する（アカウントの表示がJSTでなければ要注意）
5. Connectors欄にSlackコネクタが含まれていることを確認して「Create」

詳細: https://code.claude.com/docs/en/routines

参考: Routine実行中は対話セッションのような「ツール承認待ち」が発生しない仕様（パーミッションモードのピッカーなし）。今回`slack_send_message`が失敗したのは対話セッション特有の制約だった可能性があるが、下書き方式（オーナーの最終送信クリックを残す）は安全側の設計として維持する。

## 注意
- 同じ内容を2日連続で「至急」として送り続ける場合、対応が止まっている可能性が高いので、その旨を明記してエスカレーションする。
